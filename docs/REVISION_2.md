# 2026-10-31 第二版修订

用户自行试用反馈：绝大部分功能正常；连接外屏后内屏上滑退出等手势失效/卡顿，不能确定来自 Extend 或 Unlock。该反馈不是逐项通过证明。用户要求剩余实机测试全部跳过；本轮只做源码检查、构建及自动化测试，不连接设备、不安装、不重启。

## Extend

无障碍 onKeyEvent 原先仅凭 lastSingleAppDisplay>0 吞掉所有 HOME 事件，且 DOWN/UP 都重新启动外屏应用。现在仅处理明确属于该外屏的 HOME，且仅在未取消的 UP 启动一次；手机、其他显示器和未知显示器事件交回系统。通过项目现有 Refine/KeyEventHidden 读取事件 displayId；读取失败或 Android 10 以下不拦截。覆盖手机/背屏/未知/会话消失/外屏匹配的单元测试。

这修复了可确认的 HOME 路由缺陷，但系统导航手势未必经过 HOME 键路径，不能据此认定所有手势问题已解决。

## Unlock

增加“启用系统解锁”总开关。保留原来的默认启用行为。关闭时持久化 Secure.hyperdesktop_unlock_enabled=0 并请求 mirror_built_in_display=1；所有修改系统行为的 Hook（桌面能力、连接弹窗、镜像策略、设置保护、Computer 补写、设置页兼容）动态放行原始方法。只读外屏跟踪、签名保护控制和诊断继续工作，便于恢复开关。重新启用不自动切独立模式。

跨进程通过 Secure 设置的 ContentObserver 更新内存缓存；稳定态 Hook 不新增每次 IPC、轮询或日志。设置写入仅由既有 signature 广播入口在 system_server 执行，未增加应用权限。无法取得状态时放行系统逻辑。关闭后磁贴和独立模式按钮不可用；旧模块版本未重启时总开关不可用。

现有全局 desktop capability override、外屏焦点切换以及固件导航策略仍可能影响手势；没有性能轨迹/设备对照，不能确认卡顿根因。为避免破坏已可用的独立外屏，本轮不猜测性删改能力 Hook。关闭模块功能可隔离其影响；已创建的显示任务或系统缓存可能需重新插拔才能恢复，不能声称瞬时清除所有系统状态。

## 使用与验证边界

第二版为 debug 签名，沿用此前本机构建签名与包名。安装 Unlock 更新后需重启一次加载新代码（本轮未执行），以后总开关按运行状态生效，不需要每次重启。关闭后必要时重插外屏，重新打开再手动选择独立模式。

旧版实机记录保留；新改动的手势与开关实机回归均 SKIPPED（用户要求），不标为通过。120Hz 实际仍60Hz、设置 topology-fix 缺失、固定竖屏应用 letterbox 均未解决。无新权限或网络功能。
